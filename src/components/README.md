# components — 공용 부품 목록

> 이 폴더는 "화면을 조립할 때 꺼내 쓰는 부품 창고"예요.
> 두 종류가 섞여 있으니 표를 한 번 보고 시작하면 길이 보입니다.
>
> 📌 여기(`components/`)에는 **여러 화면이 함께 쓰는 공용 부품**만 둡니다.
> 화면 하나에서만 쓰는 코드(그 화면의 API 호출 · 훅 · 전용 컴포넌트)는 `src/features/<도메인>/` 에 두세요.

## 지금 상태 (구현 / 뼈대)

| 상태                  | 이름                                                                                                                             | 설명                                                   | 담당 배지 |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | --------- |
| ✅ 구현               | Button · GNB · Container                                                                                                         | 바로 import 해 쓰면 되는 부품이에요                    | 🔷 공용   |
| ✅ 구현 (공용 인프라) | FontLoader · `layouts/`                                                                                                          | app/layout.js 가 자동으로 쓰는 것 — 손대지 않아도 돼요 | 🔷 공용   |
| 🔨 뼈대 (③ 담당)      | SessionRefresh                                                                                                                   | app/layout.js가 호출하지만 세션 갱신 로직은 ③이 구현   | ③         |
| 🟢 공용 (기본세팅)    | Loading · QueryBoundary · Warn                                                                                                   | 화면 로딩 · 쿼리 경계 · 경고 — 그대로 쓰면 돼요        | 🔷 공용   |
| 🔨 뼈대 (주석 지침서) | Card · Checkbox · Chip · ConfirmDialog · Dropdown · Empty · Filter · Input(+TextBox) · Modal · Pagination · Search · Sort · Tabs | 폴더를 열면 **실제 파일 안에 가이드 주석**이 있어요    | ①~⑤       |

> 배지 뜻 — `①~⑤` 추천 담당 팀원 · `🔷 공용` 공용(보일러플레이트 제공 · 고쳐야 하면 담당자에게 제안).

> 뼈대 부품은 파일 상단에 📏 props 명세 · 🎨 근거 PNG · 🧱 만들기 순서 · 🧠 동작 요점이 다 적혀 있어요
> (파일 자체가 지침서인 방식이에요).

## 뼈대 부품 추천 담당 (제안 — 팀 회의에서 조정해요)

> 원칙: **자기 화면이 먼저 쓰는 부품부터 그 화면 담당자가 구현** — 몰빵이 아니라 순서만 제안해요.
> 디자인 근거는 각 부품 파일 상단의 🎨 항목(card.png 등)을 그대로 따라 주세요.

| 부품                                                      | 먼저 쓰는 화면                       | 추천 담당      |
| --------------------------------------------------------- | ------------------------------------ | -------------- |
| Card · Chip · Search · Sort · Pagination · Filter · Empty | 랜딩 · 챌린지 목록                   | **팀원 ①**     |
| Modal · Input(비밀번호 폼)                                | 로그인 · 회원가입 · 상세 모달        | **팀원 ③**     |
| TextBox · ConfirmDialog                                   | 마이페이지 소개 · 삭제 확인          | **팀원 ③ · ②** |
| Checkbox · Tabs                                           | 회원가입 동의 · 관리 목록 탭         | **팀원 ③ · ⑤** |
| Dropdown                                                  | 관리 승인·거절, 정렬                 | **팀원 ⑤**     |
| (에디터 계열)                                             | 작성 화면 — TipTap은 `app/…/edit` 쪽 | **팀원 ②**     |

> 공용 부품을 고치면 다른 화면에도 영향이 가요 — 고친 결과를 `styleguide`(부품 진열 화면)에도 함께 갱신해 주세요.

## 만들기 좋은 순서 — 의존 순서를 따르면 수월해요

부품끼리 품고 오는 관계가 있어서, 아래 순서로 만들면 앞의 부품이 뒤의 부품을 도와줍니다.

```
1) Modal · Chip · Checkbox · Dropdown · Empty · Pagination · Search · Tabs · Input(+TextBox) · Card
   (서로 겹치지 않는 독립 부품 — 좋아하는 것부터 시작해도 돼요)

2) Sort          ← Dropdown 필요
3) ConfirmDialog ← Modal · Button 필요
4) FilterDialog  ← Modal · Checkbox · Button 필요
```

- 각 뼈대 파일마다 "🧱 만들기 전에 — 먼저 완성 필요" 줄이 있으니 그대로 따라 가시면 됩니다.

## 벤치마크 표본

- **components/Button/** — 3파일 패턴(`<이름>.jsx` + `<이름>.css.js` + `index.js`)을 실제로 보여 주는 표본이에요.
  새 부품을 만들 때 구조 · 스타일 파일 분리 방식 · styleVariants 사용법을 이곳과 비슷하게 가져가 주세요.

## 궁금할 때

- 페이지에서 어디에 쓰이는지: 각 `page.js` 첫머리 주석의 "쓸 부품" 절에 화면별 관련 부품이 정리돼 있어요 (페이지는 20개 — `README.md` 트리 참고)
